# Yaesu Web Pult

Полноценный веб-пульт для трансиверов Yaesu через USB. Управляйте из браузера с ПК, ноутбука, планшета или телефона по локальной сети.

## Поддерживаемые трансиверы

- **FTX-1** (Field, Optima) — нативная полная поддержка
- **FT-710, FTDX10, FTDX101, FT-991/A, FT-891** — через Hamlib
- **FT-950, FT-450/D, FT-2000/D, FTDX3000/5000/1200** — через Hamlib
- Другие модели Yaesu — базовая поддержка через Hamlib

## Быстрый старт

### Windows

1. Скачайте **Yaesu-Web-Pult.exe** или исходники
2. Установите драйвер USB для вашего трансивера с сайта Yaesu
3. Подключите трансивер USB-кабелем
4. Запустите программу двойным кликом
5. В панели выберите модель трансивера и порты (кнопка «Найти» для автоопределения)
6. Нажмите «Запустить», затем «Открыть пульт»

### Linux / Raspberry Pi

```bash
git clone https://github.com/Evgeny161rus/yaesu-web-pult.git
cd yaesu-web-pult
pip3 install -r requirements.txt
python3 server/main.py --console
```

Откройте в браузере: `http://localhost:8080`

## Установка Hamlib (для других трансиверов)

Это исходники, не готовый EXE. Нужен Python 3.11 или новее. Распакуйте в отдельную папку, чтобы сохранить рабочую версию и её config.json.

### Для FTX-1, FT-710, FTDX10/101 и других современных Yaesu

1. Установите зависимости: `python -m pip install -r requirements.txt`.
2. Для моделей кроме FTX-1 установите Hamlib. На Windows 64-bit выполните из папки программы `powershell -File .\install-hamlib.ps1`. Скрипт скачивает официальный Hamlib 4.7.2, проверяет SHA256 и распаковывает рядом с программой, включая оригинальные лицензии. Он не меняет PATH, драйверы Windows и конфигурацию трансивера. Если запуск скрипта ограничен политикой вашей системы, можно вручную распаковать официальный hamlib-w64-4.7.2.zip и указать путь к bin/rigctld.exe в панели.
3. Запустите `python server/main.py --console`. Можно использовать прежний FTX1-Pult.pyw.
4. В панели сервера выберите драйвер «Yaesu / Hamlib», нажмите «Обновить модели» и выберите трансивер. FT-710, FTDX10/101/3000 и старые Yaesu поступают из установленного Hamlib. Статусы Stable/Beta отражают статус Hamlib, а не испытания этого пульта с каждым аппаратом.
5. Укажите CAT-порт и скорость как в трансивере, выберите звуковое устройство. У старого трансивера USB–CAT адаптер может передавать только управление: для звука нужен отдельный аудиоинтерфейс.
6. Нажмите «Запустить», затем «Открыть пульт».

Для проверки без аппаратуры выберите Hamlib → Dummy. Звук и водопад в этом режиме демонстрационные.

## Что работает через Hamlib

- Чтение и установка частоты текущего VFO; крупные цифры, ввод и валкодер.
- Режим работы из списка возможностей модели.
- AF, RF, SQL, MIC GAIN и относительная мощность (проценты), если драйвер предоставляет соответствующие чтение и запись.
- CAT PTT с существующим учётом владельца, подтверждениями клиента и таймером передачи.
- Управляемый процесс rigctld на случайном локальном TCP-порту, остановка и повторный запуск через панель.
- Полное состояние при переподключении заменяет прежние показания, не оставляя данные другого аппарата.

Текущий VFO означает VFO, выбранный на трансивере. Управление двумя независимыми VFO, память, EX-меню, калибровки измерителей и цифровые модули FTX-1 в Hamlib-режиме пока отключены. Это базовая интеграция, а не полная реализация всех функций всех Yaesu. Поддержка конкретного параметра зависит от модели, прошивки и драйвера. Команды, отклонённые Hamlib, показываются как ошибка; на обрыве связь останавливается, накопленные команды не воспроизводятся. Для восстановления используйте «Остановить»/«Запустить».

## Определение модели

Кнопка «Определить современный Yaesu по ID» работает при остановленном соединении, на выбранном порту и скорости. Она отправляет только `ID;`, с отключёнными RTS/DTR. Распознаются FT-710, FTX-1, FTDX10/101/3000/5000/1200, FT-991/A, FT-891, FT-450/D, FT-950 и FT-2000/D. Для FT-991A используется общий backend FT-991 из Hamlib.

Это не автоматический перебор всех COM-портов, скоростей и протоколов. Для старых двоичных CAT-моделей ID-проверка отключена; выберите модель вручную. USB-идентификатор адаптера не определяет модель трансивера.

## Оформление

В пульте откройте «Настройки → Оформление пульта»:

- Сохранены исходное оформление и Studio, Daylight, Heritage, Field.
- Radio Night — тёмная передняя панель: измерители слева, частота и аудиоспектр в центре, крупная ручка справа, регуляторы внизу.
- Radio Silver — та же компоновка в серебристом корпусе с тёмным зелёным дисплеем.

На высоком широком экране панель помещается в окно; на небольшом ноутбуке разрешена прокрутка, чтобы элементы не накладывались на PTT. На телефоне блоки располагаются вертикально. Выбор темы сохраняется в браузере. Спектр подписан как аудиоспектр: широкополосный SDR и захват экрана трансивера не добавлялись.

Композиционный ориентир — Radio Panel проекта MM5AGM Yaesu Web Control, найденного через DXZone. Реализация CSS/JS собственная; исходники, логотипы и изображения YWC в программу не включены.

- https://www.dxzone.com/dx37186/yaesu-web-control.html
- https://github.com/mm5agm/Yaesu_Web_Control

## Проверки и ограничения

Проверено на Windows с официальным Hamlib 4.7.2 Dummy: частота, режим, уровни, PTT, остановка процесса, повторный запуск и watchdog. В браузере Edge проверены реальный обмен WebSocket, меню моделей, ввод частоты, режим, мощность, переключение тем и мобильная компоновка. Реальные USB CAT, USB-звук, конкретные трансиверы и Raspberry Pi в этой среде не испытывались. C-расширение FT8 в тестовой среде отсутствует; FT8 не входил в эти проверки.

Тесты без Hamlib: `python -m unittest discover -s tests -v` (интеграционные будут пропущены).

Тесты с Hamlib, PowerShell:

```powershell
$env:HAMLIB_TEST_EXE = (Resolve-Path '.\tools\hamlib\hamlib-w64-4.7.2\bin\rigctld.exe').Path
python -m unittest discover -s tests -v
```

Исправлены прямые TX-команды в CAT-консоли и проверка Origin WebSocket. Административная панель без пароля допускается только при локальном TCP-соединении и loopback-адресе страницы. Открывайте её через localhost. Это не полный аудит безопасности и не настройка публичного интернет-сервиса. Reverse proxy в этой версии не настраивался. rigctld слушает только loopback. Потеря физического CAT-кабеля не позволяет программе гарантировать снятие передачи на самом аппарате.

Отдельный установочный инструмент Raspberry Pi, ARM-проверки и завершение интернет-доступа остаются следующим этапом.

## Поэтапная автономная поставка — 19 ноября 2026

Цель: пользователю не нужно вручную искать библиотеки. Это не означает отсутствие
зависимостей внутри программы. Драйверы USB и аппаратные библиотеки включаются в
установку там, где это разрешено условиями поставщика. Текущий архив — исходники,
а не готовая автономная сборка Windows или Raspberry Pi.

1. Выполнено: Hamlib загружается только при выборе этого backend или запросе его
   моделей. Штатный FTX-1 и симулятор запускаются без модуля Hamlib и rigctld.
   Полная EXE-сборка сохраняет модуль через hidden-import PyInstaller; сама
   EXE-сборка на этом этапе не выполнялась. Пройдено 10 тестов, включая отдельный
   процесс с запрещённым импортом Hamlib и интеграционные проверки Hamlib Dummy.
2. Выполнен серверный этап: общий формат кадров спектра с источником, частотной
   шкалой, единицами уровней и возрастом данных. Хранится один последний кадр;
   после секунды без обновлений возвращается stale. Новый авторизованный запрос
   spectrum_get подключён к аудиоисточнику. Браузер пока использует прежний
   протокол; переключение интерфейса будет отдельным этапом. Описание:
   server/SPECTRUM-PROTOCOL.md. Пройдено 13 тестов, включая частоту и уровень
   тестового синуса, авторизацию, устаревание, замену 10000 кадров и перезапуск.
3. USB-спектр FT-710: отдельный источник FT4222, независимый от CAT/Hamlib.
   Сначала декодирование записанных кадров и тесты, затем проверка на аппарате.
   Другим моделям поддержка не назначается автоматически по сходству CAT.
4. Внешний SDR: приём и FFT на сервере, синхронизация частоты с радио,
   явная настройка антенного/ПЧ подключения и частотного смещения.
5. Собственные CAT-драйверы добавляются по моделям с проверками; Hamlib остаётся
   дополнительным вариантом для ещё не реализованных аппаратов.
6. Raspberry Pi: отдельная ARM64-поставка, автозапуск службы, зависимости и USB-права
   через установщик; тесты восстановления USB, длительной работы, звука и сети.

Добавлен экспериментальный декодер USB-пакетов FT-710 (server/ft710_scope.py).
Проверены искусственные пакеты: 850 точек, BCD-частоты, 10 масштабов, отбраковка
повреждённых заголовков/метаданных. Cursor/Fixed пока не преобразуются в частотную
шкалу. Декодер не подключён к живому USB и не меняет CAT. Подробности и источники:
server/FT710-SCOPE.md. Реальных записей USB-потока в тестовой среде пока нет.

Добавлены отдельный транспорт FT4222 и утилита server/capture_ft710.py для записи
сырых чтений в JSONL. Выбор SPI-интерфейса — по серийному номеру, библиотеки — по
явным абсолютным путям. Проверено 23 теста, включая ошибки FTDI на имитации,
закрытие устройства и сохранение записи без перезаписи существующего файла.
Транспорт ещё не подключён к серверу; реальные USB и ARM64 не испытаны.

Живой USB-спектр и внешний SDR пока не реализованы. Наличие библиотеки под Linux не
заменяет проверки конкретной ARM64-сборки и реального трансивера.

Проверенные источники для следующего этапа:

- https://ftdichip.com/products/ft4222h/ — библиотеки FT4222 для Windows/Linux.
- https://ftdichip.com/drivers/ — требования FT4222 к D2XX/LibFT4222.
