# Архитектура Yaesu Web Pult

## Общая структура

```
┌─────────────────┐
│   Web Browser   │  ← Пульт управления (HTML/JS/CSS)
│  (любое устр-во)│
└────────┬────────┘
         │ WebSocket (JSON + Binary)
         │
┌────────▼────────┐
│  Python Server  │  ← Основной сервер приложения
│   (main.py)     │
└────────┬────────┘
         │
    ┌────┴────┬──────────┬──────────┐
    │         │          │          │
┌───▼──┐  ┌──▼───┐  ┌───▼────┐ ┌──▼────┐
│ CAT  │  │Audio │  │Digital │ │Station│
│      │  │      │  │ Modes  │ │       │
└───┬──┘  └──┬───┘  └───┬────┘ └───────┘
    │        │          │
    │   ┌────▼────┐     │
    │   │Sound    │     │

    │                   │

│ Трансивер Yaesu (любой)   │
│   (USB: CAT + Audio)      │
└───────────────────────────┘
```

## Модульная структура кода

### Основные модули

#### `constants.py`
Централизованное хранение всех констант:
- Параметры аудио (частоты дискретизации, коэффициенты)
- Сетевые параметры (порты, таймауты)
- WebSocket маркеры
- Параметры цифровых режимов

#### `station.py`
Центральный класс управления:
- Класс `Station` - координатор всей системы
- Управление клиентами (`Client`)
- Жизненный цикл связи с трансивером
- Распределение аудио потоков
- PTT арбитраж

#### `network_utils.py`
Сетевые утилиты:
- Обнаружение локальных IP
- Генерация SSL сертификатов
- Управление автозапуском (Windows)
- Проверка локальных подключений

#### `device_utils.py`
Работа с устройствами:
- Перечисление COM-портов
- Перечисление звуковых устройств
- Автоопределение FTX-1

#### `cat.py`
CAT протокол:
- Класс `Rig` - управление трансивером
- Очередь команд
- Парсинг ответов
- Auto Information режим

#### `audio.py`
Обработка звука:
- `SoundDeviceAudio` - захват/воспроизведение
- `Waterfall` - построение водопада
- `Decimator`/`Interpolator` - ресемплинг
- Джиттер-буфер TX

#### `webserver.py`
HTTP/HTTPS + WebSocket сервер:
- Собственная реализация без внешних зависимостей
- Статические файлы
- WebSocket обработчик
- SSL поддержка

### Цифровые режимы

#### `cwdesk.py`
Управление CW (телеграф):
- Декодер морзянки
- Передача через CAT или DTR/RTS
- Интеграция с AI для исправления ошибок

#### `ft8.py`
FT8/FT4:
- Декодирование слотов
- Автоматика связи
- Лог ADIF
- UDP broadcast (WSJT-X совместимость)

#### `digi.py` + `digidesk.py`
RTTY, NAVTEX, PSK31, Метеофакс, SSTV:
- Модуляция/демодуляция
- Автоподстройка
- Декодирование изображений

#### `ai.py`
Интеграция с LM Studio:
- Исправление ошибок декодера CW
- Составление ответов
- Перевод и пояснение

## Поток данных

### Приём (RX)

```
Трансивер USB Audio
    │ 48 kHz PCM float32
    ▼
SoundDeviceAudio
    │ (в отдельном потоке)
    ▼
Station._rx_from_thread()
    │ call_soon_threadsafe
    ▼
Station._on_rx_audio()
    │
    ├─► Decimator → WebSocket → Браузеры (16/8 kHz)
    │
    ├─► Waterfall → Спектр → WebSocket
    │
    ├─► CwDesk.feed()   ─► Декодер CW
    │
    ├─► DigiDesk.feed() ─► RTTY/PSK31/SSTV...
    │
    └─► Ft8Desk.feed()  ─► FT8/FT4 декодер
```

### Передача (TX)

```
Браузер (микрофон)
    │ WebSocket binary (PCM int16)
    ▼
Station._on_tx_audio()
    │ Interpolator (если не 48 kHz)
    ▼
Audio.tx.push()
    │ Джиттер-буфер
    ▼
SoundDeviceAudio (callback)
    │ 48 kHz PCM float32
    ▼
Трансивер USB Audio
```

### CAT команды

```
Браузер
    │ {'t': 'set', 'k': 'freq_a', 'v': 14074000}
    ▼
Station._on_msg()
    │
    ▼
Rig.set_param()
    │ Очередь команд
    ▼
SerialTransport
    │ COM-порт
    ▼
Трансивер
    │ Ответ
    ▼
Rig._parse_response()
    │ Обновление state
    ▼
Station._on_rig_change()
    │ {'t': 'state', 's': {...}}
    ▼
WebSocket → Все клиенты
```

## Многопоточность и асинхронность

### Потоки

1. **Главный поток (asyncio event loop)**
   - WebSocket обработчики
   - CAT команды
   - Логика управления
   - Watchdog

2. **Аудио поток (SoundDevice callback)**
   - Захват RX
   - Воспроизведение TX
   - Передача данных через `call_soon_threadsafe`

3. **Hamlib процесс** (опционально)
   - Отдельный `rigctld` процесс
   - Общение через TCP socket

### Синхронизация

- `asyncio.Lock` для критичных секций
- `call_soon_threadsafe` для межпоточной передачи
- Очереди команд в `Rig`
- Атомарные операции для PTT владельца

## Безопасность

### PTT защита

1. **Watchdog** (проверка каждые 250мс):
   - Таймаут подтверждений (1.5с без `ptt_alive`)
   - Максимальное время передачи (по умолчанию 180с)
   - Автоматическое снятие при нарушениях

2. **Арбитраж**:
   - Только один клиент может передавать
   - Проверка конфликтов с цифровыми режимами
   - Блокировка PTT при занятости

### Сетевая безопасность

1. **Авторизация**:
   - Локальные подключения без пароля
   - Удалённые требуют пароль
   - Rate limiting на попытки входа

2. **HTTPS**:
   - Самоподписанный сертификат
   - Обязателен для доступа к микрофону
   - Поддержка SAN (Subject Alternative Names)

3. **Origin проверка**:
   - Валидация WebSocket Origin
   - Защита от CSRF

## Масштабирование

### Поддержка множественных клиентов

- Set клиентов в `Station.clients`
- Broadcast сообщений всем авторизованным
- Независимые аудио потоки (8/16/48 kHz)
- Раздельные водопады с разным разрешением

### Производительность

- Децимация аудио только для нужных частот
- Ленивая генерация водопада
- Кэширование портов и устройств
- Оптимизация NumPy операций

## Расширяемость

### Добавление новых режимов

1. Создать модуль декодера (например, `psk31.py`)
2. Зарегистрировать в `digidesk.py`
3. Добавить WebSocket обработчики
4. Обновить веб-интерфейс

### Поддержка других трансиверов

1. **Через Hamlib** (универсально):
   - Выбрать модель из списка
   - Базовый функционал работает сразу

2. **Нативный драйвер** (полный функционал):
   - Реализовать CAT протокол в `cat.py`
   - Добавить модель в `yaesu_detect.py`
   - Обновить меню в `menu_*.json`

## Зависимости

### Обязательные
- `numpy` - обработка аудио
- `pyserial` - COM-порты
- `sounddevice` - звук
- `cryptography` - SSL сертификаты

### Опциональные
- `pystray` + `pillow` - трей иконка
- `hamlib` (внешний) - поддержка других моделей
- LM Studio (внешний) - AI функции

## Развёртывание

### Windows (основная платформа)
- Standalone EXE через PyInstaller
- Автоустановка зависимостей через `FTX1-Pult.pyw`
- Автозапуск через реестр Windows

### Linux / Raspberry Pi (планируется)
- systemd service
- USB permissions через udev
- Автообновление hamlib

### Docker (для разработки)
- Изолированная среда
- Воспроизводимая сборка
- CI/CD интеграция
