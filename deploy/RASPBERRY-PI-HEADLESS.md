# Yaesu Web Pult на Raspberry Pi без монитора (headless)

Подробная инструкция по установке сервера удалённого управления трансиверами Yaesu на Raspberry Pi (Raspberry Pi OS / Debian), работающем без дисплея и клавиатуры. Управление выполняется с телефона, планшета или другого ПК по сети.

## Что работает в headless-режиме

- CAT-управление, PTT, приём/передача звука (USB Audio CODEC трансивера), обычный **звуковой** водопад, панель и пульт в браузере — как на ПК.
- Запуск через systemd (`--headless`): без окна, без значка в трее, без автозапуска браузера.
- Пульт доступен по HTTPS из локальной сети (микрофон в браузере требует HTTPS).
- Широкий **аппаратный** водопад (USB-scope, FTDI FT4222) для FT-710 / FTDX10 / FTDX101 поддерживается **экспериментально**: на реальном «железе» в рамках этого релиза не проверялось. Без него автоматически используется обычный звуковой водопад.

## Требования

- Raspberry Pi с Raspberry Pi OS (рекомендуется 64-bit, Bookworm или новее) или совместимый Debian Linux.
- Сеть (Ethernet или Wi-Fi) и доступ по SSH.
- Трансивер Yaesu, подключённый по USB: порт CAT (обычно CP210x, в системе `/dev/ttyUSB*`) и, при необходимости, USB Audio.
- На ПК/телефоне в той же сети — современный браузер.

## 1. Подготовка Raspberry Pi и доступ по SSH

1. Установите Raspberry Pi OS (Lite достаточно) через Raspberry Pi Imager. В настройках Imager заранее задайте:
   - имя хоста (например `yaesu-pi`), пользователя и пароль;
   - Wi-Fi (если нужно);
   - **включите SSH** (по паролю или ключу).
2. Загрузите Pi, подключитесь по SSH:
   ```bash
   ssh <user>@<IP-адрес-pi>
   ```
3. Обновите систему:
   ```bash
   sudo apt update && sudo apt full-upgrade -y
   sudo reboot
   ```

### Последовательная консоль (serial console)

Трансиверы Yaesu подключаются по **USB** (виртуальные COM-порты `/dev/ttyUSB*`), а не через GPIO-UART Raspberry Pi. Поэтому отключать аппаратный UART обычно **не требуется**.

- Если вы не используете GPIO-последовательный порт для других целей, менять настройки serial в `raspi-config` не обязательно.
- Если когда-либо включали «login shell over serial», его можно отключить (он не нужен для USB CAT): `sudo raspi-config` → *Interface Options* → *Serial Port* → login shell **No**. Параметр «serial port hardware» для USB-CAT не критичен.

## 2. Подключение трансивера и проверка портов/звука

1. Подключите USB-кабель от трансивера к Raspberry Pi и включите трансивер.
2. Проверьте, что появились COM-порты:
   ```bash
   ls -l /dev/ttyUSB* /dev/serial/by-id/* 2>/dev/null
   dmesg | tail -n 40
   ```
   Обычно CAT — `Enhanced` порт, PTT/CW по DTR/RTS (если используется) — `Standard` порт. В Linux оба видны как `/dev/ttyUSB0`, `/dev/ttyUSB1` (порядок может меняться; предпочтительнее использовать путь из `/dev/serial/by-id/...`).
3. Проверьте USB-аудио трансивера:
   ```bash
   arecord -l
   aplay -l
   ```
   Должна быть видна карта вида `USB Audio CODEC` / `USB Audio Device`.
4. Права доступа: пользователь сервиса должен быть в группе `dialout` (доступ к `/dev/ttyUSB*`). Скрипт установки добавляет пользователя `yaesu` в `dialout` и `audio` автоматически. Если запускаете вручную под своим пользователем:
   ```bash
   sudo usermod -aG dialout,audio $USER
   # после этого нужно перелогиниться
   ```

## 3. Установка

```bash
sudo apt install -y git
git clone https://github.com/Evgeny161rus/yaesu-web-pult.git
cd yaesu-web-pult
sudo bash deploy/install-rpi.sh
```

Скрипт установит системные зависимости, создаст `/opt/yaesu-web-pult`, виртуальное окружение `.venv`, пользователя `yaesu`, установит и включит unit `yaesu-web-pult.service`.

Обновление до новой версии: снова выполните `git pull` в каталоге репозитория и `sudo bash deploy/install-rpi.sh`, затем `sudo systemctl restart yaesu-web-pult`.

Удаление сервиса: `sudo bash /opt/yaesu-web-pult/deploy/uninstall-rpi.sh` (файлы и `config.json` останутся) или с `--purge` для полного удаления.

## 4. Настройка (`config.json`)

Основные настройки хранятся в `/opt/yaesu-web-pult/config.json`. Настроить можно **до** первого запуска (или изменить позже и перезапустить сервис).

### Интерактивный настройщик по SSH (рекомендуется)

Удобный консольный скрипт без графики: показывает доступные CAT/tty-порты и аудиоустройства, умеет **автоопределять** порт/звук, а также **опрашивать трансивер (CAT ID)** — определяет модель и возможности (в т.ч. поддерживается ли аппаратный USB-scope/широкий водопад для FT-710/FTDX10/FTDX101) и подсказывает, что настроить. Изменения сохраняются в `config.json`.

```bash
sudo -u yaesu /opt/yaesu-web-pult/.venv/bin/python /opt/yaesu-web-pult/server/configure.py
# или (если установлен скрипт-обёртка):
sudo bash /opt/yaesu-web-pult/deploy/configure-rpi.sh
# после сохранения перезапустите сервис, если настройщик не сделал это сам:
sudo systemctl restart yaesu-web-pult
```

> Опрос модели работает, когда трансивер включён, подключён по USB и выбран верный CAT-порт/скорость (CAT RATE в меню трансивера). Автоопределение использует те же эвристики, что и программа (CP210x/Enhanced port, USB Audio CODEC).

### Ручное редактирование

```bash
sudo nano /opt/yaesu-web-pult/config.json
sudo systemctl restart yaesu-web-pult
```

Минимально важные параметры:

| Параметр | Назначение | Пример / примечание |
|---|---|---|
| `cat_port` | Порт CAT | `/dev/ttyUSB0` или стабильный `/dev/serial/by-id/usb-Silicon_Labs_...-if00-port0` |
| `cat_baud` | Скорость CAT | Должна совпадать с меню трансивера (CAT RATE), обычно `38400` |
| `ptt_method` | PTT | `TX1` (рекомендуется, по CAT), либо `TX2`, `RTS`, `DTR` |
| `ptt_port` | Порт для RTS/DTR PTT | Нужен только если PTT по линии отдельного порта |
| `audio_in_name`, `audio_out_name` | Звуковая карта трансивера | Часто можно оставить пустыми (автоопределение USB Audio CODEC). Если не угадалось — задайте точное имя устройства (см. ниже) |
| `password` | Пароль для входа по сети | **Обязательно задайте**, если будете открывать пульт не с самого Pi |
| `http_port` | Локальный HTTP (панель) | по умолчанию `8080` |
| `https_port` | HTTPS для сети (пульт) | по умолчанию `8443` |
| `http_lan` | Отдавать HTTP и в сеть | `false` по умолчанию; для пульта с телефона используйте HTTPS-порт |
| `auto_connect` | Подключаться к трансиверу при старте | `true` для автономной работы |
| `simulate` | Симулятор без трансивера | `false` для реальной работы |

Чтобы узнать точные имена аудиоустройств и портов в окружении сервиса:

```bash
sudo -u yaesu /opt/yaesu-web-pult/.venv/bin/python /opt/yaesu-web-pult/server/main.py --list
```

> Панель управления (`/panel`) доступна **только локально** на машине, где запущен сервер. На headless-Pi для настройки удобно использовать интерактивный скрипт `server/configure.py` по SSH или править `config.json` (см. выше), а управлять трансивером — через пульт/HTTPS. При необходимости доступ к панели можно получить через SSH-туннель: `ssh -L 8080:127.0.0.1:8080 <user>@<pi>` и открыть `http://127.0.0.1:8080/panel` на своём ПК.

## 5. Запуск и управление сервисом

```bash
sudo systemctl start yaesu-web-pult      # запустить сейчас
sudo systemctl enable yaesu-web-pult     # автозапуск при загрузке (устанавливается скриптом)
sudo systemctl status yaesu-web-pult     # состояние
sudo systemctl restart yaesu-web-pult    # перезапуск после правки config.json
```

Журнал (в реальном времени):

```bash
sudo journalctl -u yaesu-web-pult -f
```

При старте сервер создаст самоподписанный сертификат (`cert.pem`, `key.pem`) рядом с `config.json`, если его ещё нет — это нужно для HTTPS/микрофона.

## 6. Доступ с телефона и других устройств

1. Узнайте IP-адрес Raspberry Pi: `hostname -I`.
2. Откройте в браузере: `https://<IP-Raspberry-Pi>:8443/`
3. Браузер предупредит о самоподписанном сертификате — это нормально для локальной сети: нажмите «Дополнительно» → «Перейти на сайт (небезопасно)».
4. Введите пароль, заданный в `password`. На Android в Chrome можно выбрать «Установить приложение» для режима, похожего на отдельное приложение.

Требования: устройство и Pi должны быть в одной сети; порт `8443/tcp` должен быть доступен (если включён файрвол — разрешите его). Не открывайте сервер в интернет без дополнительной защиты (VPN/обратный прокси с нормальным TLS и аутентификацией).

## 7. RF-водопад: USB-scope FT4222 и внешний RTL-SDR

По умолчанию водопад строится из USB-аудио (`waterfall_source: audio`). Для широкого RF-водопада доступны два дополнительных источника.

### 7.1. USB-scope FT4222 (экспериментально, FT-710 / FTDX10 / FTDX101)

Читает аппаратный панорамный приёмник через интерфейс FTDI **FT4222 A** (SPI) с помощью библиотек **LibFT4222** и **D2XX**. Это **не** CAT-порт.

- **Статус:** экспериментально, на реальном оборудовании может требовать проверки выравнивания/масштаба. При ошибке сервер переключается на звуковой водопад.
- **Нужные библиотеки (Raspberry Pi — ARM64/aarch64):** `libft4222.so` и при необходимости `libftd2xx.so` для вашей архитектуры. Файлы FTDI не поставляются с проектом — скачайте их с сайта FTDI.
- **Настройка в `config.json`:**
  ```json
  {
    "waterfall_source": "auto",
    "scope_libft4222": "/opt/ftdi/build/libft4222.so",
    "scope_d2xx": "/opt/ftdi/build/libftd2xx.so",
    "scope_serial": ""
  }
  ```
  - `scope_serial` можно оставить пустым (описание `FT4222 A`) или указать серийный номер SPI-интерфейса.
- **На трансивере:** должен быть включён вывод спектра на SCU/USB-scope (см. руководство к трансиверу/wfview, зависит от модели/прошивки).
- Интерфейс FT4222 не должен быть занят другой программой; CAT работает отдельно.

### 7.2. Внешний RTL-SDR (USB донгл)

Подходит для трансиверов без аппаратного USB-scope (в т.ч. FTX-1). Пульт запускает `rtl_sdr`, считает FFT и показывает RF-водопад вокруг текущей частоты VFO-A. При уходе VFO за край окна обзора RTL-SDR ретюнится с дебаунсом.

- **Установка:** `sudo apt-get install -y rtl-sdr librtlsdr-dev`. Скрипт `deploy/install-rpi.sh` и `server/configure.py` (пункт «Источник водопада») определяют подключённый RTL-SDR и предлагают установить пакеты; также пишут `/etc/modprobe.d/blacklist-rtl-sdr.conf`, чтобы DVB-драйвер не захватывал донгл после перезагрузки.
- **Настройка в `config.json`:**
  ```json
  {
    "waterfall_source": "rtlsdr",
    "rtlsdr_sample_rate": 1024000,
    "rtlsdr_gain": 40
  }
  ```
- **Hot-swap:** при отключении RTL-SDR на работающем сервере водопад автоматически переключается на аудио; при повторном подключении устройство обнаруживается и RF-водопад возвращается (для `waterfall_source: rtlsdr/auto`).
- **Ограничения:** типичный R820T RTL-SDR принимает ~24–1766 МГц; прямой HF-приём зависит от конкретной модели (например RTL-SDR v3 direct sampling). Окно обзора определяется sample rate (по умолчанию ~1.024 МГц) и центрируется около VFO.

### Общие замечания

- `waterfall_source`: `auto` — доступный RF-источник, иначе звук; `scope` — только FT4222; `rtlsdr` — только RTL-SDR; `audio` — только звук.
- На вкладках RX/TX/VFO при живом RF-источнике используется RF-водопад. Цифровые режимы (RTTY/FT8/CW-декодер и т.п.) используют звуковой водопад, где им нужны звуковые частоты/декод.

## 8. Типовые проблемы

- **`/dev/ttyUSB*` не появляются:** проверьте кабель/питание трансивера, `dmesg`; убедитесь, что ядро видит CP210x (`lsmod | grep cp210x`).
- **`Permission denied` на COM-порт:** пользователь не в `dialout` → `sudo usermod -aG dialout yaesu` и перезапуск сервиса.
- **Нет звука / устройство не найдено:** проверьте `arecord -l`, имена в `audio_in_name`/`audio_out_name`, уровни ALSA (`alsamixer`, выберите USB-карту F6), что устройство не занято.
- **Сервис не стартует:** `sudo journalctl -u yaesu-web-pult -e` — смотрите трассировку. Частые причины: неверный `config.json` (синтаксис), занятый порт, отсутствует зависимость в venv.
- **Телефон не открывает пульт:** проверьте IP, одну сеть, порт `8443`, файрвол (`sudo ufw status`), задан ли `password`.
- **После перезагрузки порядок `/dev/ttyUSB0/1` поменялся:** используйте стабильные имена из `/dev/serial/by-id/` в `cat_port`/`ptt_port`.
- **USB-scope не работает:** проверьте пути к `.so` и архитектуру (ARM64), права, что интерфейс не занят, что `waterfall_source` не `audio`, и логи (`USB-scope не используется` / причина). Звуковой водопад продолжит работать.
- **RTL-SDR не работает:** проверьте `lsusb` (виден `0bda:2838/2832`), наличие `rtl_sdr` (`which rtl_sdr`), что DVB-драйвер не захватил донгл (после установки blacklist нужна перезагрузка или `modprobe -r dvb_usb_rtl28xxu ...`), и логи (`RTL-SDR: ...`). Для HF прямой приём обычного R820T-донгла обычно недоступен.

## 9. Полезные команды

```bash
# Логи
sudo journalctl -u yaesu-web-pult -f

# Проверка портов/аудио из окружения сервиса
sudo -u yaesu /opt/yaesu-web-pult/.venv/bin/python /opt/yaesu-web-pult/server/main.py --list

# Ручной запуск в консоли (для отладки, предварительно остановите сервис)
sudo systemctl stop yaesu-web-pult
sudo -u yaesu /opt/yaesu-web-pult/.venv/bin/python /opt/yaesu-web-pult/server/main.py --headless --console
```
