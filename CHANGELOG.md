# Changelog

Все значимые изменения в проекте документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/),
и проект следует [Semantic Versioning](https://semver.org/lang/ru/).

## [Unreleased]

### Исправлено

- Windows: фоновый водопад RTL-SDR/SoapySDR больше не открывает мигающее
  DOS-окно — `rtl_sdr`/`rx_sdr`/`hackrf_transfer` запускаются с
  `CREATE_NO_WINDOW` (в том числе при переподключениях и перестройке).
- Windows: данные перенесены в профиль пользователя, сняты широкие права записи в папку программы; запуск после установки без повышения прав.
- DX: обновления спотов больше не закрывают открытые настройки подключения.
- DX: повреждённая строка с чрезмерно большой частотой больше не останавливает приём спотов.
- Релизы: теги `windows-latest` и `pi-latest` указывают на коммит опубликованной сборки; публикации выполняются последовательно.
- Установщик Windows: журнал установки драйверов и пустые папки удаляются при деинсталляции.

### Добавлено

- **Любые трансиверы через Hamlib**: список моделей всех производителей,
  фильтр по производителю и дополнительные аргументы `rigctld`
  (`hamlib_extra`, например `-C civaddr=0x94` для Icom).
- **PTT линией RTS/DTR в режиме Hamlib**: если драйвер не умеет PTT,
  CAT-управление продолжает работать, а передача включается отдельной линией.
- **Раздельные устройства звука приёма и передачи**: внешняя USB-звуковая
  карта может иметь разные устройства PortAudio для входа и выхода.
- **DX-споты (DX-кластер)**: вкладка «DX-споты» принимает поток DXSpider
  (по умолчанию `dxc.hamserve.uk:7300`), хранит до 500 спотов и переподключается
  при обрыве. Фильтры по диапазону/виду/возрасту/стране, метки «уже работал»
  и «новая страна», подписи позывных над RF-водопадом, перестройка только
  приёмного VFO по двойному клику. Передача, вид работы и SPLIT не меняются.
- **SpotRadio (spotradio.ru)**: второй источник DX-спотов — публичный JSON-поток
  без позывного и telnet-входа. Выбирается в настройках DX, опрашивается раз в
  20 секунд; работают те же фильтры, метки и перестройка приёмного VFO.
- **Меню настройки при установке Raspberry Pi** (whiptail, как в `raspi-config`):
  трансивер и CAT, модель Hamlib, отдельные устройства звука приёма/передачи,
  PTT (CAT/RTS/DTR), источник водопада и пароль панели.
- **Установщик Windows `Yaesu-Web-Pult-Setup.exe`**: ставит программу в
  `C:\Program Files\Yaesu Web Pult`, сразу включает Hamlib 4.7.2 и RTL-SDR,
  ставит драйверы FTDI (включая FT4222) и Silicon Labs CP210x, добавляет
  ярлыки и Zadig для RTL-SDR. Портативные EXE/ZIP остаются в релизе.
- [docs/RADIO-SUPPORT.md](docs/RADIO-SUPPORT.md) — матрица поддерживаемых
  моделей, настройка CAT/PTT/звука и устранение неполадок.

### Исправлено

- Hamlib: вместо пустой ошибки `Hamlib:` показывается текст от `rigctld`
  (порт/скорость/кабель) или подсказка при таймауте.
- Hamlib: отсутствующий локальный CAT-порт обнаруживается за ~0.05 с вместо
  нескольких секунд ожидания; сетевые порты (NET rigctl) не блокируются.
- Панель: список Hamlib по умолчанию показывает всех производителей, а не
  только бренд сохранённой модели.
- Панель: один запрос пароля при удалённом входе вместо серии повторных
  `admin_denied`.
- Ошибка подключения больше не «висит» после Stop/сохранения настроек.
- RTL-SDR работает и в режиме симулятора (внешний SDR не зависит от CAT).
- DX: перестройка по споту сразу отображается в пульте, не дожидаясь эха
  `FA`/`FB` от трансивера (раньше частота менялась на сервере, но не в браузере).
- Установщик Raspberry Pi больше не исключает встроенный `server/cty.dat`:
  шаблоны сохранения `config.json`/`cty.dat` привязаны к корню каталога и не
  затрагивают одноимённые файлы внутри `server/`.
- В архив Raspberry Pi теперь входит `server/cty.dat`: страны для FT8 и
  DX-спотов доступны сразу после чистой установки, без обращения к интернету.
- Raspberry Pi: пользователь сервиса `yaesu` добавляется в группу `plugdev`.
  Без неё `rtl_sdr` не мог открыть USB-донгл после чистой установки
  (`/dev/bus/usb/...` доступен только группе `plugdev`), и водопад уходил на звук.

### Изменено

- **Оформление, компоновка и размер кнопок разделены**: 7 тем отвечают только
  за цвета, компоновка (классическая, управление справа, передняя панель, DX)
  и размер кнопок выбираются отдельно. Старые настройки переносятся автоматически.
- **DX-споты передаются инкрементально**: полный список приходит при подключении,
  дальше — только новые, обновлённые и удалённые записи. Это заметно снижает
  трафик удалённого доступа (полный список до 500 спотов каждые 0.5 с давал
  сотни килобайт).
- Установщик Raspberry Pi вместо одного вопроса о пароле открывает меню
  настройки (whiptail); в неинтерактивном режиме меню пропускается.
- Установщик Raspberry Pi спрашивает пароль для веб-панели и сохраняет его в
  `config.json`; обновление не перезаписывает рабочий `config.json`.
- Установщик очищает `__pycache__`/`.pyc`, чтобы старый байткод не запускался
  после обновления.

## [3.2-preview] - 2026-11-19

### Переименование проекта

**FTX-1 Пульт → Yaesu Web Pult**

Проект теперь универсальный пульт для различных трансиверов Yaesu, не только FTX-1.

### Удалено

#### Функции локального ИИ
- Удалена интеграция с LM Studio для совместимости с Raspberry Pi
- Удалены AI endpoints из сервера
- Удалены конфигурационные параметры `ai_*`
- Удалён модуль `server/ai.py`

**Причина**: Языковые модели требуют мощное оборудование (8+ GB RAM, GPU).
Несовместимо с целевым использованием на Raspberry Pi и бюджетных мини-ПК.

#### Архитектура и код
- **Модульная структура**: Выделены отдельные модули для улучшения maintainability
  - `constants.py` - централизация всех констант и магических чисел
  - `station.py` - основная логика управления станцией
  - `network_utils.py` - сетевые утилиты (SSL, автозапуск, IP)
  - `device_utils.py` - работа с COM-портами и аудио устройствами
- **Улучшенная типизация**: добавлены type hints для основных модулей
- **Расширенное тестирование**: новые тесты для модулей utils и констант (11 тестов)
- **CI/CD пайплайн**: 
  - `lint.yml` - проверка качества кода (flake8, pylint, mypy)
  - `tests.yml` - автоматическое тестирование на Python 3.11-3.13, Windows/Linux
  - Health checks и resource limits

#### Документация
- `docs/WEBSOCKET_PROTOCOL.md` - полная документация WebSocket протокола
- `docs/ARCHITECTURE.md` - детальное описание архитектуры проекта
- `CONTRIBUTING.md` - руководство для разработчиков
- `CHANGELOG.md` - история изменений

#### Инфраструктура
- `requirements.lock` - точные версии зависимостей для воспроизводимых сборок
- `.flake8` - конфигурация линтера
- `pytest.ini` - настройки тестирования
- Улучшенный `.gitignore` с полным покрытием Python-проектов

### Изменено

- **CW режим**: теперь работает полностью без ИИ
  - Автоответ по шаблонам вместо генерации ИИ
  - Разбор принятого по правилам Q-кодов
  - Декодер работает как и раньше (встроенный DSP)

- **RTTY, NAVTEX**: убраны функции перевода через ИИ
  - Весь функционал декодирования сохранён
  - Работает на любом оборудовании

### Добавлено
- Поддержка Hamlib для других трансиверов Yaesu
- Темы оформления: Radio Night, Radio Silver
- USB-спектр FT-710 (экспериментально)
- Транспорт FT4222 для FT-710
